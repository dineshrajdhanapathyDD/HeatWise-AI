# HeatWise M2 second pass: weather-summary seam fix, prior safety findings still open

Since the first review, the only code change is an integration fix. The Weather Agent now runs `check_text_claims` on its free-text summary, using `weather_evidence_numbers` (which includes forecast °F conversions). The risk agent reuses that helper, so a summary that the Weather Agent keeps can no longer fail safety on its own. Three tests were added and the README and tasks.md counts were updated to 177. None of the four findings from the first pass were addressed. `verification_tools.py`, `coordinator.py`, `cli.py`, `planner_agent.py` and the SKILL.md files are unchanged since that review, and each finding still reproduces against the current code.

Watch for: (confirmed) emergency or phone numbers in model-written text still pass every deterministic check. (confirmed) a plan that fails safety is still written out as a normal checklist.

**Verdict**: NEEDS_CHANGES

## High-level view

Fail-closed handling of numbers in free text is still missing. "call 108", "Dial 112 or 911", "+91 98765 43210" in general advice, and "dial 112" in the plan intro all give `passed` with no issues. The task forbids invented emergency numbers, and 911 is wrong for India.

The export path is unchanged too. `build_report` and `cli assess --checklist-out` render the failing plan's checklist with no status banner, and the rejected items are still in it. The minor diagnosis-pattern gap and the planner prompt gap (`list_guidance` called once per audience x phase) also remain.

Sources, thresholds, deterministic category and pass/fail, no external actions, and the community-level-only profile were confirmed in the first pass. This pass does not change them.
