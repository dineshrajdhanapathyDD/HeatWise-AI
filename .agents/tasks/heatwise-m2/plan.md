## Design decisions (made during planning, grounded in code read)

D1. Data moves between agents in code, not through the LLM. The coordinator holds a `CoordinatorRun` state object. Its tools (`weather_intelligence`, `community_risk`, `action_planner`, `safety_verifier`, `finalize_report`) are thin `@tool` closures that call each specialist's `.run(...)` with the state and return a compact JSON summary to the model. This keeps the Module 6 agents-as-tools pattern (each tool invokes a specialist Strands Agent) without asking Nova to copy large JSON blobs, which M1 showed it does unreliably. Specialists still expose `as_tool()` for standalone use, matching `weather_agent.py`.

D2. Ordering is enforced by `OrderingSteeringHandler(SteeringHandler)` from `strands.vended_plugins.steering` (verified in the installed 1.63.0: `Guide` sets `event.cancel_tool` with the reason). It reads `CoordinatorRun` state directly rather than `LedgerProvider`, so decisions depend only on completed specialist results. The coordinator agent uses `strands.tools.executors.SequentialToolExecutor` (verified to exist, and `Agent(tool_executor=...)` is accepted) so a model that emits two delegations in one turn cannot race the steering check.

D3. Deterministic completion. After the coordinator agent returns (or raises), `_complete_pipeline()` runs any step the model skipped, under the same rules (including the single revision), and records those calls in the trace with `agent="coordinator_fallback"` plus a note in `missing_information`. The report therefore never finalises without safety verification, even if Nova stops early. GraphBuilder is not needed unless the trajectory tests show the steering approach failing; if so, document why in design.md.

D4. Risk is pure rules in `backend/services/risk_rules.py`:
- Current heat index from current air temperature + relative humidity using the NWS/WPC Rothfusz algorithm (simple formula first, averaged with T; if >= 80°F apply the regression and the low-RH / high-RH adjustments). Verified at https://www.wpc.ncep.noaa.gov/html/heatindex_equation.shtml (fetched during planning).
- Heat index bands from https://www.weather.gov/ama/heatindex (fetched during planning): Caution 80-90°F, Extreme Caution 90-103°F, Danger 103-124°F, Extreme Danger >= 125°F. Hazard score 0 (< 80°F), 1, 2, 3, 4. The same page gives two chart anchors usable as tests: 100°F/55% -> 124°F and 100°F/15% -> 96°F, and states the equation's error is ±1.3°F.
- Forecast daily max air temperature against IMD actual-maximum criteria, as published on WHO India https://www.who.int/india/heat-waves (fetched during planning): heat wave considered only if max >= 40°C (plains) / >= 30°C (hilly); actual max >= 45°C = heat wave, >= 47°C = severe heat wave; declared when met at >= 2 stations in a sub-division for >= 2 consecutive days. Used as an indication for a forecast grid point, never an official declaration. Score: >= 47 -> 4, >= 45 -> 3, >= 40 -> 1. Departure-from-normal criteria need climatological normals we do not have, so they are reported as missing data. Applied when terrain is "plains" or unknown (unknown is listed as missing data, plains assumed); for "hilly"/"coastal" the actual-max rule is not applied and that is listed as missing data.
- Open-Meteo `apparent_temperature` is a different metric from the NWS heat index, so it is shown as evidence but not fed into the bands.
- Vulnerability adjustment is a labelled, configurable PROJECT HEURISTIC (not an official standard): if hazard >= 1 and the number of vulnerability indicators >= `risk_vulnerability_min_indicators` (default 2), raise one category step, capped. Indicators (community-level presence only, never individuals): elderly, young_children, pregnant_women, chronic_illness_group, outdoor_workers, farmers, limited_water_access, limited_shade_or_cooling. The WHO fact sheet (https://www.who.int/news-room/fact-sheets/detail/climate-change-heat-and-health, fetched) supports that age, occupation and housing shape vulnerability; cite it as rationale only, not for the numbers.
- Category = score 0 low, 1 moderate, 2 high, 3 very_high, 4 extreme; `unknown` with status `insufficient_data` when no current conditions and no forecast.
- Confidence: high = current temp+RH and forecast present, not stale, terrain known; medium = one of those missing/stale or terrain unknown; low = only current or only forecast.

D5. Planner content comes from a verified guidance catalog (`backend/guidance/catalog.py`) with source ids from `backend/guidance/sources.py`. The LLM selects items via tools (`list_guidance`, `select_guidance(audience, phase, guidance_ids: str comma-separated)`, `add_general_advice(audience, phase, text)`), and the plan is assembled from the ledger, like weather. This avoids list-typed structured output (the M1 Nova failure). Structured output is only `PlanIntro{intro: str}`. Deterministic fill: every audience x phase gets at least one item, and each audience's plan must cover hydration, rest, shade and escalation; missing topics are added from the catalog with `added_by="rules"`. SKILL.md files (AgentSkills plugin, Module 3) hold per-audience composition instructions; the `skills` tool name is from `AgentSkills.skills` in the installed SDK and must be on the planner allowlist as an uncounted tool.

D6. Language: M2 guidance text is English only, because translated text cannot be verified against sources. `SUPPORTED_PLAN_LANGUAGES = ("en",)`. Any other requested language gives `language="en"` plus `language_notice`. Recorded as a gap in tasks.md findings.

D7. Safety pass/fail is decided only by deterministic checks. The optional LLM review (`SafetyReview{concern: str | None}`) can add non-blocking warnings shown in the report, but can never pass a failed plan or fail a passed one. `settings.safety_llm_review` (default True) toggles it.

D8. Sources: `backend/guidance/sources.py` is the single sources list (id, title, publisher, url, verified_on, what was verified). Only pages actually fetched go in. Already verified during planning: `nws_heat_index` (weather.gov/ama/heatindex), `wpc_heat_index_equation`, `who_india_heat_waves`, `who_heat_health_factsheet`. The coder must fetch further sources for outdoor-worker and farmer guidance and for an emergency number (candidates to try: https://www.osha.gov/heat-exposure, CDC/NIOSH heat stress pages, https://112.gov.in which timed out during planning). NDMA material is mostly PDF, which `web_fetch` cannot read; skip PDFs rather than cite them unread. If no emergency number is verified, escalation text says "contact local emergency services or the nearest health facility" with no number.

D9. No external actions: no tool can send messages; guardrail allowlists stay closed; the report carries a fixed notice that HeatWise does not send alerts or contact anyone.
