## High-level view

Phone and emergency number rejection is now on by default for every model-written text. Model text that contains a number falls back to the deterministic text. The cases from the earlier reviews ("call 108", "Dial 112 or 911", "+91 98765 43210", intro "dial 112", "911" in a risk explanation, "108" in a weather summary) are rejected and have tests. Temperatures such as `108°F` are excluded by a unit lookahead. No catalog item matches any banned pattern. The remaining gap is short Indian service numbers (100, 101, 102, 1070) that appear with no keyword. The pattern list only names "call/dial/phone/helpline/number" and the three short codes.

On `needs_human_review`, the exported checklist now holds only `verified_item_ids`, under a "Not verified - needs human review" banner plus the review notice. The full plan stays in `recommended_actions` in the report JSON for the reviewer. tasks.md tells M3 not to render those items as advice. Coordinator and CLI tests assert that "aspirin" is missing from the exported markdown.

Earlier passes confirmed the sources, thresholds, deterministic category and pass/fail, closed tool allowlists, no external actions, and the community-level-only profile. Those files (`sources.py`, `risk_rules.py`, `risk.py`, `catalog.py`) have not changed since then. design.md §8 documents the checklist rule and the `can_finalize` steering change. It does not mention the phone-number rule, which is only recorded in tasks.md findings.
